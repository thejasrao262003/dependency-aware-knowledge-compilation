**Answer:**

> The knowledge base covers what happens when an upload goes over the body size limit. It says nothing on a cap for the number of uploaded files, and I found no separate "form parsing limit".
>
> **When an upload exceeds the limit**
>
> - **413 response.** FastAPI stops reading and returns an HTTP 413 Content Too Large response, if the response hasn't started yet. FastAPI counts the bytes it reads, even when the client sends the body in chunks without a `Content-Length` header. (`advanced/request-body-limits.md`, "What counts toward the limit?")
> - **What counts.** The limit applies to the whole request body. Every file, any form fields, and the bytes used to encode the multipart form all count toward one limit. The URL and headers don't count. (`advanced/request-body-limits.md`)
> - **`UploadFile`.** A file can move from memory to disk as it grows, but its contents still count toward the same limit. (`advanced/request-body-limits.md`)
> - **Middleware.** If middleware reads the body before FastAPI picks a path operation, the app's limit applies to that read. In the doc's example, middleware calling `await request.body()` rejects a 2 MiB upload before it reaches a router that allows 100 MiB. (`advanced/request-body-limits.md`, "Middleware that reads the body")
>
> **Limiting the size of uploads**
>
> - **Setting it.** Set `max_body_size` in bytes on the `FastAPI` app, then override it on an `APIRouter` or a single path operation. You can also pass it to `include_router()`. (`advanced/request-body-limits.md`)
> - **Example from the doc.** `POST /items` gets 1 MiB from the app, `POST /uploads/` gets 100 MiB from its router, and `POST /uploads/small` gets 10 MiB of its own. (`advanced/request-body-limits.md`)
> - **Defaults.** If you leave it at `None`, it inherits from the router or app. If you set no limit anywhere, the body size is unlimited. `0` allows only an empty body. (`advanced/request-body-limits.md`)
>
> **Limiting the number of files**
>
> The knowledge base has no setting for this. `advanced/request-body-limits.md` only limits total bytes, so a cap on file count isn't documented here. `tutorial/request-files.md` only says you can declare a list of `bytes` or `UploadFile` to accept several files. I didn't find anything on `max_files` or `max_fields` in that page's claims or passages. I haven't read the full source text of `tutorial/request-files.md`.
>
> The cap on total size does indirectly bound how many files fit in one request. If you need a hard count, you'd have to check `len(files)` in your own handler. That is my suggestion and isn't from the knowledge base.

> **What happens when a form upload exceeds the parsing limits**
> - FastAPI passes the limit settings to Starlette when it parses a request for a `Form`, `File` or `UploadFile` parameter. This includes parameters declared in dependencies. (`advanced/request-body-limits.md`)
> - Exceeding a parser limit returns HTTP 400. (`advanced/request-body-limits.md`)
> - Starlette caches the parsed form on that request. (`advanced/request-body-limits.md`)
> - For URL-encoded forms, Starlette counts the encoded name and value together against the limit. (`advanced/request-body-limits.md`)
> - A default of 1 MiB is stated for one of these limits. (`advanced/request-body-limits.md`) The compiled claim doesn't say which limit that is, so check the document before relying on it.

> **How to limit the number of uploaded files**
> - Use `max_files`, which sets the maximum number of files in a multipart form. The default is 1,000. (`advanced/request-body-limits.md`)
> - To bound the whole request, including the contents of uploaded files, use `max_body_size`. (`advanced/request-body-limits.md`)
